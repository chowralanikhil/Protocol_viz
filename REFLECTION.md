# Reflection: Application Layer Lab

I used OpenAI Codex desktop with the GPT-5.6 Codex agent. I chose it because it could read the assignment brief, turn the required interface into a working implementation, and help check message sequencing in one workflow. I used the agent for layout planning, implementation, protocol examples, and supporting documentation; the accompanying AI usage log records those stages.

The dashboard remains synchronized through one event-driven state model in the browser. Pressing **Visit**, **Send email**, or **Start stream** builds the appropriate ordered list of protocol events and sets the active step to the first one. The visualization panel renders from that same list. Its timed playback changes the active step, while the previous, next, pause/resume, and replay buttons all update the same state. Therefore an action in the left panel has an immediate, visible counterpart in the right panel.

The AI-generated initial concept needed protocol review. For mail, a generic hostname lookup would be misleading: mail routing normally needs a DNS MX record, followed by a connection to the selected mail exchanger. The final simulation shows that MX response before the SMTP greeting and uses the expected SMTP command sequence: `EHLO`, `MAIL FROM`, `RCPT TO`, `DATA`, and `QUIT`. For adaptive streaming, it would also be inaccurate to portray the session as one large download. The final flow uses HTTP to retrieve a master manifest, a quality-specific playlist, and independent media segments. Real deployments often use HTTPS and may have additional redirects, authentication, caching, or TLS negotiation; those are intentionally outside this application-layer-focused simulation.

The activities make the contrasting protocols concrete. Browsing begins with DNS resolution and then usually consists of a request-response HTTP exchange for a resource. Mail is more conversational and command-oriented: the client and SMTP server negotiate in a sequence of short commands and status replies, with a message body sent during `DATA`. Streaming begins with DNS and HTTP too, but HTTP is used repeatedly: the client first learns the available variants and then requests short segments over time. This explains how an apparently continuous video can adapt quality while remaining ordinary HTTP traffic at the application layer.
